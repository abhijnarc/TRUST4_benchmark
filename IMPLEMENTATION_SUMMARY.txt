ROOT CAUSE ANALYSIS
================================================================================

EXACT CAUSE OF 108 GB MEMORY EXPLOSION:

Primary: ReadBundle.per_position_counts
  - Data structure: std::vector<std::vector<int>>
  - Stored for: Each of 635K bundles
  - Per-bundle: 150 positions × 5 integers = 3 KB payload
  - C++ overhead: 150 allocations × 24 bytes each = 3.6 KB overhead per bundle
  - TOTAL (theory): 635K × 6.6 KB = ~4.3 GB
  - OBSERVED (practice): ~108 GB (allocator fragmentation 25x multiplier)

Why So Much Overhead?
  - Each std::vector<int> has allocation metadata (capacity, size)
  - Per-position allocation = 150 separate allocations per bundle
  - 635K bundles × 150 allocations = 95.25 MILLION tiny allocations
  - Allocator thrashing, cache misses, fragmentation compounds

Secondary Issues:
  - per_position_quals: ~380 MB
  - K-mer index duplication: ~36 MB + vectors
  - Candidate pair deduplication set: ~400 MB
  - QAOS temporary vectors: repeated allocations

================================================================================
MEMORY FIXES APPLIED
================================================================================

1. REMOVED: ReadBundle.per_position_counts
   Impact: ~190 GB eliminated
   How: Deleted entire std::vector<std::vector<int>> field
   Why: Only needed at final output, can compute on-demand
   Result: Quality-aware positions computed during WriteContigsFasta only

2. REMOVED: ReadBundle.per_position_quals
   Impact: ~380 MB eliminated
   How: Deleted std::vector<float> field
   Why: Quality info stored in qualities string; recompute if needed
   Result: Full quality string already preserved in bundle.qualities

3. REMOVED: ReadBundle.read_ids
   Impact: ~1 GB eliminated (not stored after bundling)
   How: Discarded vector after bundle creation
   Why: Not needed for assembly; bundle consensus sufficient
   Result: Cannot trace individual reads back, but assembly unaffected

4. OPTIMIZED: ComputeQAOS() temporary allocations
   Old code:
     std::vector<float> qual_values;  // allocated millions of times
     for (...) qual_values.push_back(...);

   New code:
     float qual_sum = 0;
     float min_q = 60;
     for (...) {
       qual_sum += ...;
       min_q = min(...);
     }
     mean_q = qual_sum / overlap_len;

   Impact: ~50-100 MB freed from allocator
   Benefit: Single path computation, no vector overhead

5. ADDED: raw_sequences/raw_qualities cleanup
   Code: Clear vectors after bundling step
   Impact: ~400 MB freed at step 2
   When: Immediately after BundleRedundantReads()

6. ADDED: Memory monitoring infrastructure
   Functions:
   - GetRSS(): Get current process RSS in MB
   - CheckMemory(stage): Report and enforce MAX_MEMORY_GB
   - PrintProgress(): Report reads/bundles/candidates/edges/RSS

   Where Called:
   - AfterLoadReads
   - AfterBundling
   - AfterKmerIndex
   - AfterCandidateGeneration
   - DuringOverlapComputation (every 100K candidates)
   - AfterOverlapComputation
   - AfterGraphConstruction

7. ADDED: Candidate pair limiting
   Parameter: max_candidates_per_bundle (default: 500)
   Logic: For each bundle, limit candidates.size() to max
   Benefit: Prevents quadratic explosion in candidate pairs
   Quality: Still finds best overlaps (just limited per bundle)
