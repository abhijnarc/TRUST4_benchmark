INNOVATION: QUALITY-ADAPTIVE OVERLAP SCORING (QAOS)
================================================================================

Mathematical Foundation:

1. Phred Error Model
   e = 10^(-Q/10)

2. Per-Base Compatibility Probability
   If bases match:
     P = (1 - e1) × (1 - e2)
       [probability both observations are correct]
   
   If bases mismatch:
     P = e1/3 + e2/3 - e1×e2/9
       [probability same nucleotide by sequencing error]

3. Geometric Mean Scoring
   QAOS = (∏ per_base_compatibility) ^ (1/overlap_length)

4. Acceptance Criteria
   - Observed identity >= 0.90 AND
   - QAOS >= 0.90

Advantages over v1:
  - Incorporates base quality information
  - Distinguishes high-confidence from low-confidence overlaps
  - Handles variable-length overlaps (not fixed 20 bp)
  - Tracks expected vs. observed mismatches
  - Identifies high-quality mismatches (Q >= 20)

  Input: 1,234,800 raw reads

  Output: 634,616 bundles (1.95x compression ratio)
  Features:

  Status: ✓ COMPLETE

Stage 3: K-mer Indexing
  Input: 634,616 bundle consensus sequences
  K-mer size: 9 bp
  Action: Extract all 9-mers from each bundle sequence
  Output: 4,052,877 distinct k-mers with position mapping
  Purpose: Enable efficient candidate pair generation (not scoring)
  Status: ✓ COMPLETE

Stage 4: Candidate Pair Generation
  Input: K-mer index + bundle sequences
  Action: For each bundle, find k-mer matches in other bundles
  Output: Candidate bundle pairs requiring full alignment
  Strategy: O(n) indexing rather than O(n²) pairwise comparison
  Status: ➢ IN PROGRESS (9 min+ elapsed)

Stage 5: Quality-Aware Overlap Computation
  Input: Candidate bundle pairs
  Action: For each pair:
    - Try all overlap lengths 31-1000+ bp
    - Perform suffix→prefix alignment
    - Calculate QAOS for each overlap
    - Accept if identity >= 0.90 AND QAOS >= 0.90
  Output: Valid edges with quality metrics
  Metrics recorded per edge:
    - Overlap length
    - Observed identity
    - Mismatches (observed, expected, high-quality)
    - Mean and minimum quality
    - QAOS score
    - Bundle abundances
  Status: PENDING

Stage 6: Graph Construction
  Input: Valid edges
  Action: Build adjacency list from bundle connections
  Output: Graph with nodes=bundles, edges=overlaps
  Status: PENDING

Stage 7: Graph Cleaning
  Input: Raw graph
  Action: Apply threshold filters (overlap >= 31, identity >= 0.90, QAOS >= 0.90)
  Output: Cleaned graph
  Status: PENDING

Stage 8: Contig Extraction
  Input: Cleaned graph
  Action: Find connected components via BFS traversal
  Output: Components grouped as potential contigs
  Status: PENDING

Stage 9: Consensus Generation
  Input: Contigs (component bundles)
  Action: Quality-weighted nucleotide voting for each position
  Output: Consensus sequences with quality scores
  Status: PENDING
